# Where each key goes

Nothing in this project needs a secret to run: the deterministic runtime, the URL checks, the UI and every test work with an empty `.env`. Keys are needed only for the **AI agent** runtime (your choice of provider) and for **OpenClaw**. All of them live in the git-ignored `.env` at the repository root; `.env.example` lists the names with empty values. Never commit `.env` and never paste a key into a file that is tracked by git.

```bash
pnpm run setup        # creates .env from .env.example and generates SENTINEL_AGENT_TOKEN (never bare `pnpm setup`: that is pnpm's own command)
```

## The AI agent runtime (one provider at a time)

`LLM_PROVIDER` selects the provider; the runtime uses the key and model variables of that provider only.

| Provider | `LLM_PROVIDER` | Key variable | Model variable | Default model if the model variable is empty |
|---|---|---|---|---|
| Anthropic | `anthropic` (the default) | `ANTHROPIC_API_KEY` | `ANTHROPIC_MODEL` (also `ANTHROPIC_EFFORT`, default `medium`) | `claude-opus-5-5` |
| OpenAI | `openai` | `OPENAI_API_KEY` | `OPENAI_MODEL` | `gpt-6-astra` |
| Google Gemini | `gemini` | `GEMINI_API_KEY` | `GEMINI_MODEL` | `gemini-3.5-flash` |

Example `.env` lines for OpenAI (the value after `=` is your key; keep it on that one line, no quotes needed):

```
LLM_PROVIDER=openai
OPENAI_API_KEY=<your key>
OPENAI_MODEL=
```

**To switch provider:** change `LLM_PROVIDER`, make sure that provider's key is set, then **restart the API** (`.env` is read at start; with Docker, `docker compose up -d --force-recreate api`). The other providers' keys can stay in the file; they are ignored.

**Who can read `.env`:** any agent that has file tools in this folder (Claude Code, Codex, Cursor, Antigravity) can read `.env`, including the provider keys. Use a dedicated, low-privilege, spend-capped key for this project (not your main one), keep `.env` out of any shared workspace, and do not open this folder with an agent you do not trust.

**Model ids** are the defaults taken from the providers' official documentation while the project was built (2026-10-17). They change over time; if a provider rejects a model, set the model variable to one your account can use (the run then ends `FAILED / MODEL_CONFIG_ERROR` naming the variable).

### How to confirm it works

1. `GET http://localhost:4000/api/health` (Docker: the API port you published, 4000 by default) shows the selected provider:

   ```json
   "runtimes": { "ai": { "provider": "openai", "model": "gpt-6-astra", "status": "available" }, … }
   ```

   `status` is `available` when the key of the selected provider is set, `missing_key` when it is empty, `unknown_provider` when `LLM_PROVIDER` is not one of the three. Without any key the same call reports `"status": "missing_key"` (that is what a fresh clone shows).
2. In the UI, the start form's runtime selector shows **AI agent** as selectable only when `status` is `available`; otherwise it is disabled with the reason ("The provider API key is not set in .env."). `/integrations` shows the same status and the provider and model.
3. Start an investigation with the AI agent: the run page shows the runtime `ai` and the model as `<provider>:<model>`.

### Gemini notes

- Working example: `LLM_PROVIDER=gemini` and `GEMINI_MODEL=gemini-3.5-flash-lite`.
- Model ids are lowercase with dashes (`gemini-3.5-flash-lite`), not the display names shown in Google's UI.
- To list the ids available to your key, make a read-only request to `https://generativelanguage.googleapis.com/v1beta/models` with the key sent in the `x-goog-api-key` header, never in the URL.
- Free-tier per-minute limits differ per model. A model limited to 5 requests per minute cannot finish an investigation, which makes about 8 to 10 requests.
- Verified once: run `cmvcipil00000dsxfnzevlau5` with `gemini-3.5-flash-lite` on a free-tier key completed in about 16 s (details: [verification.md](./verification.md)).

**Honest status:** the Gemini session was run once against the real API (one run, one campaign, free-tier quota). The Anthropic and OpenAI sessions are tested only against fake HTTP transports (one shared conformance suite); no key was available for them, so they were not run against the real APIs. See [verification.md](./verification.md).

## OpenClaw

OpenClaw has its own model credentials and its own install. The variables Sentinel needs are `OPENCLAW_GATEWAY_URL`, `OPENCLAW_GATEWAY_TOKEN` and `OPENCLAW_AGENT_ID` (default `sentinel`); the exact install, onboarding, config fragment and verification steps are in [openclaw.md](./openclaw.md). `/api/health` then reports `"openclaw": "configured"`. Status: **experimental**, not run on a real OpenClaw install.

## Agent API token (for Claude Code, Codex, Cursor, Antigravity, OpenClaw)

`SENTINEL_AGENT_TOKEN` is generated by `pnpm run setup`. The API checks it on `/api/agent/*`; the MCP server (`apps/mcp`) reads it from the repository `.env` itself, so it appears in none of the committed IDE config files. Without it the Agent API answers 401 and IDE agents cannot start investigations. In Docker, `docker compose` passes `SENTINEL_AGENT_TOKEN` and the provider variables from your shell or the root `.env` into the API container.

## Not secrets, but worth knowing

| Variable | Meaning |
|---|---|
| `BROWSER_CHECKS` | `auto` (use Chromium if installed) or `off`. The Docker image has no Chromium, so `browser_check` is `unavailable` there. |
| `URL_FETCH_ALLOW_PRIVATE` | Test-only switch that lets the URL tools reach loopback addresses (the local fixture site). The API refuses to start with it when `NODE_ENV=production`. Leave it empty. |
| `SENTINEL_API_URL` | Where the MCP server finds the API when it is not `http://127.0.0.1:API_PORT`. Loopback hosts only: the agent token is sent there, so a remote host makes the server refuse to start unless `SENTINEL_ALLOW_REMOTE_API=1` is set. |
